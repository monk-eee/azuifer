## Not verified against Azure

These choices rest on Microsoft Learn, which is silent or inconsistent on them. A recording from a premium NFS share would settle each:

1. The status and code of an SMB-only operation on an NFS share (chosen: 403 XNfs4ShareDeniedException), and of an NFS-only operation or header on an SMB share (chosen: 400 InvalidQueryParameterValue or InvalidHeaderValue).
2. What an NFS share does below x-ms-version 2025-05-05 (chosen: behaves the same; only the link operations are version gated).
3. Whether SMB-only headers are rejected or ignored on NFS, and POSIX headers on SMB (chosen: ignored).
4. Get File, Put Range, Put Range From URL, List Ranges, Copy File, Create File and Set File Properties (resize) on a symbolic link, and a hard link to a symbolic link or a directory (chosen: XNfs4FileTypeUnsupportedException, InvalidHeaderValue).
5. The default mode of a symbolic link (chosen: 0777), the link count of a directory (not reported), and the casing of the file type on Get File Properties (SymLink).
6. Whether a missing parent on Create File and Create Directory is 404 ParentNotFound, as here, or the 412 that one Learn page names.
7. The default x-ms-file-mode-copy-mode and x-ms-file-owner-copy-mode when omitted (chosen: source).
8. How symbolic links are listed, and whether their Content-Length is the text length (chosen: listed as files, length of the text).
9. The access tier and quota Azure reports for a premium NFS share.
10. Whether Create File over a hard-linked name truncates the shared file (chosen) or replaces the name.

Until then every NFS operation is `known-difference` in [the manifest](../../specs/conformance/file.json), and none is `exact`.
